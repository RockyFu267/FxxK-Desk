# 可视化监控区域

监控区域独立于任何软件。用户决定截取哪一块屏幕、位置和尺寸，再把需要观察的软件放入该区域。

```powershell
$env:PYTHONPATH = 'src'
.\.venv\Scripts\python -m fxxk_desk.cli region
```

- 拖动绿色边框移动区域，支持负坐标和不同位置的显示器。
- 拖动四角或边缘的八个控制点缩放。
- 在设置窗口选择屏幕，或点“铺满该屏”。
- 可输入精确的 X、Y、宽、高，再点“应用”。
- “保存并查看状态”才会写入配置，并保留状态面板；不会自动启动采集。取消或 Esc 保留上次配置。
- 框内部不覆盖透明窗口，因此可以直接操作放在框内的软件。

默认最小尺寸为 640×480 物理像素，可通过 `--min-width`、`--min-height` 调整。最大限制为当前所选显示器范围，另有 16,777,216 像素的采集预算。区域始终位于单块显示器内，避免把多屏之间不存在的桌面空隙纳入截图。跨屏拖动或切换屏幕时会自动约束边界。

默认本地配置为 `artifacts/capture-region.local.json`，保存物理坐标、所选屏幕和尺寸限制，不上传 Git。再次打开编辑器会读取上次区域。显示器布局变化后请重新确认。

## 保存之后怎么看运行状态

保存只是配置完成。状态面板明确显示“区域已保存 · 尚未启动监控”，不能把配置存在或边框可见当作正在运行。

点“开始监控（仅区域采集）”后，程序每次采集完成等待 5 秒再采集，更新采集帧数和最近检查时间，并仅保留最新截图。它不调用模型、不点击软件、不转述消息。可点击“查看最近截图”检查实际采集内容，点“停止采集”停止。关闭面板会停止由该面板启动的本地采集。

绿色边框表示控制台启动的区域采集正在运行，最小化面板后仍保留。停止、暂停、出错或状态失联时隐藏。蓝色带控制点的框仅表示配置预览。运行框不接收鼠标输入，并使用 Windows 截图排除机制避免进入采集图片。如果面板挡住所选区域，采集会暂停，移开或最小化面板后恢复。

控制台提供软件选择（当前仅企业微信）、任务类型、监控群、通知群、自动发送、轮询间隔、区域调整、开始/停止、最近截图和最小化。聊天设置写入 `config.local.toml`，保留原有布局校准和其他字段。任务类型和间隔写入区域旁的私有 settings.local.json，均不上传 Git。

选择“群消息转发”时，“开始任务”启动实际转述工作流；取消自动发送则只生成待发摘要，不会清空原有队列。默认轮询间隔 5 秒，允许 2～3600 秒；每轮结束后等待，忙碌时会加快检查。首次启动先建立当前消息基线，之后处理新消息。软件窗口必须完整位于监控框内，且仍需符合已有聊天布局校准。

高级设置提供程序路径、窗口标题、历史回翻开关、最多回翻页数、回翻时限、用户停止操作后的等待时间、前台恢复要求及滚动方式。运行中锁定设置，停止后才能修改。关闭控制台会协作停止任务；进行中的截图、OCR 或模型请求结束可能需要等待，不会强制杀进程。

控制台转述任务支持三屏区域隔离：框外输入不打断未遮挡源群的只读观察和摘要，但滚动、切群、发送必须等待全部输入空闲且软件在前台。后台读到的连续消息先持久化，底部与历史完整性在可以操作时重新核验。锁屏或远程桌面不可用时暂停，不会尝试解锁。详见 [人工接管](human-takeover.md)。

## 工作预告和鼠标准备位置

面板启动的区域采集、群转述任务，在首次执行及每轮定时触发时，都会在所有已连接屏幕顶部显示三阶段提示：默认 3 秒“即将开始”倒计时；倒计时结束后持续显示“程序正在工作”；操作结束后显示“本轮操作完成，可以继续使用电脑”约 2 秒再消失，直到下一轮开始。条件不足后的重新尝试也重新预告。暂停、停止和出错分别显示对应结束信息，不冒充成功。操作过程退出后才显示结束提示。

工作线程必须等待主线程确认“正在工作”提示已显示后，才能开始采集和输入。提示窗口不抢焦点、不接收鼠标，并由系统排除截图，所以工作时无需隐藏。停止任务会取消尚未结束的倒计时，后续不再点击或采集。

高级设置可调整提示时长（1～30 秒）、是否每个动作前后复位鼠标，以及准备位置的物理 X/Y 坐标。默认位置为监控区域所在屏幕左上角向内 16 像素。聊天任务在一轮开始时初始化；每次点击、滚动、快捷键和整段文字输入前后，都回到准备位置并核验实际坐标。普通鼠标移动是底层定位步骤，不会立即复位，点击前仍须核对目标位置。

动作失败、用户接管或锁屏时，不强行执行收尾复位，下一次重试会重新预告和初始化。纯截图任务不移动鼠标。鼠标复位提供一个可校验的准备状态，不能阻止用户之后继续移动指针。

选择“仅区域采集”时，只保存最新截图，不调用模型或发送消息；间隔允许 0.1～3600 秒。模型密钥仍通过本地 `.env` 设置。

```powershell
# 重新打开保存区域的状态面板。
fxxk-desk region --status
# 命令行查看真实任务状态。
fxxk-desk status
```

运行任务通过本地心跳文件报告状态。界面区分启动、观察、采集、总结、发送、用户接管暂停、停止、出错和状态失联；同时检查进程是否存在，过期或已退出的任务不会仍显示正常监控。聊天转述任务的状态也能显示，但它使用独立的应用适配配置，不会因保存选框而自动启动。

## 使用已保存的区域

```powershell
.\.venv\Scripts\python -m fxxk_desk.cli observe-region
# 可选：将缩小后的区域图发送给已配置的视觉模型。
.\.venv\Scripts\python -m fxxk_desk.cli observe-region --analyze
```

默认保留原始分辨率截图到 `artifacts/region.png`；`--analyze` 才会生成最长边 1024 像素的模型输入，并调用网关。编辑器持有桌面工作流锁，避免自动任务和选框操作同时进行；保存或取消后释放。

## 采集范围与软件适配

这里的最小/最大尺寸是截图能力和操作体验的限制，不代表任意软件在这个范围内都能被可靠识别。软件文字大小、DPI、布局和消息类型仍然影响 OCR。

现有聊天适配器的 `layout_width`、`layout_height`、`message_rect`、`editor_rect` 和 `send_point` 仍然独立校准。本版没有将选框自动套入旧的聊天点击坐标，也没有把任意界面按比例缩放后盲点。通用区域可以立即用于截图和视觉观察；软件自动操作必须在对应适配完成后启用。

## 验证

几何测试覆盖负坐标、跨屏拟合、最小/最大尺寸、固定对边缩放、像素预算、无效配置及原子保存。2026-11-23 在三屏实机验证了切屏、铺满屏幕、框位置的物理坐标、640×480 最小区域保存及按保存区域截图。GUI 布局已截图检查，当前共 80 项单元测试通过。
