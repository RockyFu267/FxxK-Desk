# FxxK-Desk

[中文](README.md) | [English](README.en.md)

**让难以自动化的桌面软件，也能自动操作。**

**FxxK** 是我们对技术的四个期待：**Freedom（自由）· eXploration（探索）· eXpertise（专业）· Knowledge（知识）**。Desk 代表桌面，也是这些理念落地的地方：让用户拥有选择，让探索变成工具，让专业与知识减少重复劳动。

面向缺少开放接口、限制自动化接入的桌面软件，探索通过屏幕理解与桌面交互完成重复工作。

有些软件始终珍视人与电脑之间的亲密关系，坚持让每一次点击都带着本人的温度。这份对手工劳动的守护，在今天已经不多见了。

这些精心照料用户体验的软件，连鼠标该由谁来点，都替我们考虑得十分周到。我们也想做一点小小的体验优化：让用户偶尔可以不在电脑前，依然不辜负这些值得反复点击的设计。

## 我们想做什么

- 看懂界面：截图、OCR、视觉模型，识别内容与界面状态。
- 执行操作：点击、输入、滚动、切换窗口，并检查操作结果。
- 持续工作：观察变化、触发任务、记录进度，出错后恢复。
- 探索新路：可以是 RPA、类 RPA、视觉 Agent，也可以是自己设计的新交互方式与框架。

研究重点之一，是减少自动化交互中容易被识别的机械特征，探索更接近日常人工操作的方式；实际可检测性需要验证，不承诺无法检测或不会封号。

## 实现方向

围绕 **观察 → 理解 → 操作 → 验证** 建立闭环。优先从 Windows 开始，结合视觉感知、本地 AI、鼠标键盘控制与可用的系统接口，按实际效果选择技术，不预设唯一方案。

核心能力与应用适配分离，数据默认本地处理。先跑通一个小任务，再逐步提高稳定性和通用性。

## 当前状态

已有最小 Python 脚手架：窗口发现、软件启动与切换、窗口截图、内网视觉模型接入。安装与命令见[本地开发说明](docs/development.md)。视觉识别与桌面操作的完整闭环仍待实际验收。

另有实验性的聊天与单向转述流程：配置来源和接收会话、采集可见消息、SQLite 记录与去重、总结发送者和内容并转发。独立程序已通过一次真实桌面转述闭环测试；持续运行与更多消息类型仍待验证。

已加入[刷屏补采方案](docs/backfill-design.md)：消息锚点、重叠滚动、断档记录、独立摘要线程和持久化队列。模拟 1000 条突增消息与实机 8 条多行刷屏补采测试通过，持续高速运行仍待验证。

像素校准批量滚动已做实机 A/B：同一批 8 条消息无漏采、无重复，总截图由 122 次降至 75 次，单轮耗时由 66.1 秒降至 56.1 秒；不同设备和负载下需重新测量。

已加入[人工接管机制](docs/human-takeover.md)：用户操作时暂停，空闲且回到目标应用后重新观察；发送中断保留草稿或标记不确定，不自动重发。原生输入自测和实际窗口滚动验证已通过，长期共用桌面仍待验证。

仅在本人或获授权的账号与环境中实验。
